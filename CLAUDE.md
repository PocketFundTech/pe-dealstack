# CLAUDE.md

## Reminders

- ~~AI classifier needs a current-date injection~~ — **fixed 2026-09-28 (PR #144).** `aiExtractor.ts` already injected the date; the gap was the now-live Claude extraction engine (`extraction/extractionSchema.ts`'s `EXTRACTION_SYSTEM_PROMPT`/`EXCEL_CONTAINER_INSTRUCTION`, used by `extraction/claudeEngine.ts`), which were static constants. Both are now builder functions taking `getTodayIso()` at call time. Verify any new extraction/classification prompt does the same — `grep -rn getTodayIso apps/api/src/services` to see every call site that already does.
- **New Claude call sites should use prompt caching when the prefix repeats.** Confirmed via the `UsageEvent` ledger (2026-09-28): extraction is the dominant cost driver, and a call site with no `cache_control` was quietly re-billing the full system prompt + document on every repair pass and container→text fallback. `claudeFinancialClassifier.ts`, `financialCrossVerify.ts`, `dealChatAgent/index.ts` and (as of PR `perf/extraction-prompt-caching`) `extraction/claudeEngine.ts` all mark their stable prefix `cache_control: { type: 'ephemeral' }`. When adding a new Claude call that resends the same system prompt or document across multiple calls in one run, do the same — it changes nothing about the request/response, only the bill.
- **NDA signature push detection is disabled outside prod.** Drive `files.watch` (webhook + cron) is commented out in `apps/api/src/app-lite.ts` and `apps/api/src/services/legalDocSendService.ts` because `*.vercel.app` can't be GCP-domain-verified. Active detection runs via on-demand polling (`legalDocSignaturePollService` + `POST /legal-documents/check-signatures`). Before shipping to the verified custom domain, re-enable push — steps in `docs/nda-signature-detection-setup.md` ("Enabling push in production").
