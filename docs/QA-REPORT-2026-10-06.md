Tested with a real Chromium browser (Playwright) against production, using both a disposable QA org and the founder's real account (`GAsjab`). This file is written for an engineer/agent to work through and fix — each finding has reproduction steps, evidence, and a status.

## 1. Balance sheet doesn't balance on Luktara Industries

**Status: 🟡 root cause fixed, stored data not yet repaired.**

Opening Luktara Industries Pvt. Ltd. (Due Diligence stage, 93% extraction confidence) shows the product's own validator flagging 32 validation flags, including 10 hard errors — five "Balance sheet doesn't balance" errors (e.g. Assets $134.1M ≠ Liabilities $134.1M + Equity $41.6M = $175.7M) plus several "FCF mismatch" warnings.

Root cause and fix: see finding #11 below — this and #11 are the same underlying bug (unit-scale extraction). Fixed in PR #196. **Once #196 merges and deploys, click "Re-extract" on Luktara's Financial Statements panel** — this re-runs extraction with the fixed merge logic and should resolve most of these flags. No manual DB repair should be needed (the fix lives in the extraction/merge code path, not a one-time migration).

## 5. Settings sub-nav scroll-spy gets out of sync

**Status: 🔴 Open.**

The left sub-nav in Settings is supposed to highlight whichever section is in view. Confirmed broken in two ways:
- After clicking a nav link, the highlight sometimes lands on the wrong item (clicking "Security" scrolled correctly but highlighted "Team"; clicking through Firm Profile → Integrations → API Keys → Webhooks → AI Usage left both "Webhooks" and "AI Usage" highlighted at once).
- Scrolling to the very bottom of the page (AI Usage / Deactivate Account) leaves "Notifications" highlighted instead of updating.

Routing (URL hash) is always correct — only the visual highlight is wrong. Likely a race condition in the IntersectionObserver-based scroll-spy, or an off-by-one in the section boundary calculation for the last section.

## 6. React hydration error #418 on Dashboard / Data Room

**Status: 🔴 Open.**

A minified React hydration mismatch error (`Error: Minified React error #418`) fires in the browser console on full-page loads of both `/dashboard` and `/data-room`. Reproduces 100% of the time on both pages. Since it reproduces on two unrelated pages, likely a shared layout/provider component rendering something (a date, a locale-formatted string, relative time) differently server-side vs client-side.

On Data Room this coincided with the page being visibly stuck on skeleton loaders for 3-5 seconds before correcting to the proper empty state.

**Fix direction:** `vercel logs` + React DevTools to find the shared component; check anything using `Date.now()`, `new Date()`, `Math.random()`, or locale-dependent formatting without a client-only guard.

## 9. "Change Stage" button opens "Close Deal", not a stage picker

**Status: 🔴 Open.**

On a deal's detail page, the pipeline shows stage circles (Initial Review → Due Diligence → ... → Closing) plus a button labeled "Change Stage" above them.

- Clicking an **individual stage circle** correctly opens a "Change Deal Stage" dialog with the right before/after preview (e.g. Initial Review → Due Diligence).
- Clicking the **"Change Stage" button itself** instead opens a "Close Deal" dialog (Closed Won / Closed Lost / Passed) — it's actually a close-deal shortcut, mislabeled as general stage control.

A user trying to move a deal from Initial Review to Due Diligence who clicks the prominently-labeled "Change Stage" button will be confused to see only terminal outcomes.

**Fix direction:** either rename the button to "Close Deal" to match what it does, or make it open the real stage picker (matching the circles' behavior) and add a separate, clearly-labeled "Close Deal" action.

## 11. Financial model shows impossible returns (942% IRR, 122,597x MoM) — unit-scale extraction bug

**Status: 🟡 Root cause fixed in PR #196 (open, unmerged — https://github.com/PocketFundTech/pe-dealstack/pull/196). Luktara's already-stored data not yet repaired.**

On the real Luktara Industries deal, "Build model" showed Base case **MoM 122,597.6x, IRR 942%, Exit EV $1,593,173.7m**, with Low/High cases just as absurd (IRR 865%-1,017%). The deal's own Revenue (LTM) tile shows $3.0M.

**Root cause:** unit scale is not normalized across chunks of the same document during extraction. The income statement read $212.6M → $321.1M for 2007-2013, then jumped to **$362.5B in 2014** and **$583.0B in 2021** (both from the same source file, `1_income_statement_model_1_0.xlsx`), tagged **95% confidence** — roughly 1,000x too large. `mergeStatementsBySameType` was keeping the first sibling's `unitScale` and silently applying it to all siblings ("first-wins"), even when a later sibling's chunk was detected at a different scale (thousands vs millions).

**Fix (PR #196), test-first with full red→green verification:**
1. `mergeStatementsBySameType` (`apps/api/src/services/financialPeriodNormalizer.ts`) now converts every sibling statement into the first one's unit scale before merging, instead of first-wins with mismatched raw numbers. `_pct` and `_source` fields are left untouched.
2. New `unit_scale_break` validation error (`apps/api/src/services/financialValidator.ts`, `unitScaleBreakFactor`) fires when adjacent-year revenue moves within 3% of an exact 1,000x or 1,000,000x ratio, naming both periods.
3. New `implausibleReturnsNote` (`apps/api/src/services/dealModel/scenarios.ts`) warns in the model panel, the Low/Base/High cases view, and the exported Excel's Notes sheet when IRR > 100% or MoM > 20x — verified to correctly stay **silent** on a clean deal (Apex Precision Manufacturing: 49.8% IRR / 7.56x MoM) so it won't false-positive on healthy deals.

**Verification already done:** 268/269 test files, 2537/2587 tests pass; `tsc --noEmit` clean; red→green cycle manually verified by reverting the fix and re-running the new tests (9 failures), then restoring (47/47 pass). New regression tests reproduce the exact Luktara numbers.

**Remaining work:**
- [ ] Merge PR #196
- [ ] After deploy, click "Re-extract" on Luktara Industries' Financial Statements panel to fix its stored data (should not need a manual DB migration — the fix is in the extraction/merge path, so re-running extraction should self-heal)
- [ ] Spot-check 1-2 other real deals' financial statements for the same mixed-scale pattern, in case Luktara isn't the only one affected

## 12. Production AI out of credits; raw billing error leaks into memos and exported PDFs

**Status: 🔴 Open — re-confirmed 2026-10-06 on a second, independent test (Apex Precision Manufacturing memo).**

Creating a memo returns Anthropic's `"Your credit balance is too low to access the Anthropic API. Please go to Plans & Billing to upgrade or purchase credits."` for every AI-generated section. This blocks all AI features in production, including the financial-extraction-accuracy test this QA round was originally meant to run with real input files.

**Worse: the raw API error JSON (including request IDs) is written directly into the memo body** — not caught, not replaced with a friendly message — and **carried into the exported PDF**. Confirmed on two separate memos (QA Smoke Test Room, and again on Apex Precision — Owner Retirement Buyout, 2026-10-06). A user could send that PDF to an investment committee or a prospect, and it tells them your AI vendor account ran dry.

**This has two parts:**
1. **Account/billing issue** (not a code fix) — restore Anthropic credits. Per this repo's own `CLAUDE.md`: *"When AI features fail in production, check credit first: `vercel logs --environment production --since 1h --query 'credit balance'`. Anthropic and OpenAI both ran out of credit on 2026-09-28 and again 2026-10-01."* — now also 2026-10-06. This keeps recurring; worth a permanent fix (auto-reload, a higher balance threshold, or a billing alert) rather than a one-off top-up each time.
2. **Code fix, independent of #1** — the raw error string must never be saved into a memo section or exported into a PDF. Find the section-generation code path (search for `Section generation failed:` — the literal string baked into the saved section content) and replace it with a friendly placeholder, e.g. *"AI is temporarily unavailable — retry later."* that is clearly marked as not-yet-generated content and is excluded from PDF export.

## 13. Client portal: un-watermarked downloads, Revoke doesn't invalidate issued links

**Status: 🔴 Open.**

Internal Data Room downloads are watermarked with the downloader's email and a UTC timestamp (confirmed by decoding the PDF content stream) — a genuinely good VDR feature. But the **client portal** (the audience most likely to leak a document externally) serves the **original, un-watermarked file**, byte-identical to the upload, through a 1-hour Supabase signed URL.

**Two confirmed issues:**
- The portal download is not watermarked, unlike the internal download.
- After clicking **Revoke** on a share link, the portal page correctly shows "This link has been revoked" — but the **already-issued download URL still returns the file with HTTP 200** (tested directly via `curl` against the signed Supabase storage URL after revocation).

Also noted: the portal's "Overview" card is completely blank (no text, not even a "no overview yet" placeholder), and share links default to "Never expires".

**Fix direction:**
- Apply the same watermarking used for internal downloads to the portal's document endpoint.
- Either make the signed URL genuinely short-lived and re-validate the share's revoked status on every file access (stream through the API instead of a direct storage redirect), or revoke/rotate the underlying storage token when a share is revoked.
- Default new share links to an expiry (e.g. 30 days) instead of "Never expires".
- Fill or hide the blank Overview card.

## 14. All NDA outputs require Google Workspace; downloads fail silently

**Status: 🔴 Open.**

Without a connected Google account, all four ways to get an NDA out fail: Send via email, Download .docx, Download PDF, and even Send for signature via Dropbox Sign (it renders the PDF via Google first). A firm on Microsoft 365 cannot produce a single NDA through this product.

The downloads fail with **no message shown to the user at all** — the backend has the right text (`"Google isn't connected — open Settings → Integrations to download."`) but it's only logged to the browser console, never surfaced in the UI. The e-signature dialog does show an error, but it's **duplicated** ("Couldn't render the document to PDF: Couldn't render the document to PDF: ...") and the only button is "Retry", which will fail the same way every time since nothing changed.

**Fix direction:**
- Render PDFs/.docx server-side (e.g. via a library like `docx`/`pdf-lib` or a headless-Chrome print) instead of depending on Google Docs, so non-Google firms aren't blocked.
- Surface the existing, already-correct error message in the UI instead of only the console.
- Fix the duplicated error string in the e-signature dialog; replace "Retry" with something actionable like "Connect Google" when that's the actual blocker.

## 16. Memo Builder: unreadable at 1280px, duplicate sections, image-only PDF

**Status: 🔴 Open — re-confirmed 2026-10-06 on a second, independent test.**

### 16a. Layout crushed at 1280px
At 1280px wide (a standard laptop), three side panels (left nav, section list, AI Analyst chat) squeeze the memo canvas to ~230px. The memo title breaks mid-word, and section headings render one letter per line, vertically (e.g. "EXECUTIVE SUMMARY" becomes "E / X / E / C / U / T / I / V / E ..."). At 1920px the same page renders fine. Re-confirmed on a fresh memo (Apex Precision — Test Memo) on 2026-10-06.

**Fix direction:** collapse the AI Analyst panel (or the section list) automatically below ~1440px viewport width.

### 16b. Five duplicate sections
Every memo generated from the Standard IC Memo template has 17 sections where 12 are expected — these five appear twice: Quality of Earnings, Management Assessment, Operational Deep Dive, Value Creation Plan, Exit Analysis (sections 6-17 of 17, confirmed by heading text and position in two independent memos). Choosing "Blank memo" in the creation dialog still applies the Standard IC Memo template and its duplicate-section bug.

**Fix direction:** find wherever the Standard IC Memo template's section list is defined/seeded and de-duplicate it.

### 16c. Image-only PDF export
`Export to PDF` takes 10+ seconds with no progress indicator (the button looks dead while it works — same "no feedback" pattern as finding #8). The resulting PDF is image-only: embedded as JPEG pages, not searchable or copyable text, despite the memo being plain text/headings in the editor. ~745KB-1.25MB for a few pages of mostly text.

**Fix direction:** generate the PDF from the actual text/HTML content (e.g. via a proper HTML-to-PDF renderer) instead of rasterizing a screenshot of the page.

### 16d. Raw AI error leaks into the document and PDF
Same root cause as finding #12 — see that entry for the fix. Re-confirmed in this round's PDF export (`Apex Precision — Owner Retirement Buyout` memo, 2026-10-06): every section shows the raw `Section generation failed: 400 {"type":"error",...}` JSON, baked directly into the exported PDF.

## 18. Workspace creator gets MEMBER role, not admin

**Status: 🔴 Open.**

Confirmed on two independent fresh signups ("QA Smoke Test Capital" and "QA Sample Deal Capital") — the person who signs up and creates a brand-new workspace is assigned the **MEMBER** role, not an admin/owner role. A founder who signs up for their own firm can't create API keys or webhooks for their own org, and has to ask an admin who doesn't exist yet.

**Fix direction:** in the signup/workspace-creation flow, the first user of a new organization should be assigned ADMIN (or OWNER) role, not MEMBER.

## 19. Gmail / Google OAuth connect — ✅ FIXED, verified 2026-10-06

**Status: ✅ Fixed and verified.**

Previously broken: `POST /api/integrations/gmail/connect` and `POST /api/integrations/google_calendar/connect` both returned `503 {"code":"INTEGRATION_NOT_CONFIGURED","message":"Google sign-in isn't set up on this server yet."}`, with **no error shown anywhere in the UI** — the Connect button appeared to do nothing.

**Verified fix (2026-10-06):** both buttons now return `200` and correctly redirect to a real, fully-branded Google OAuth consent screen (`accounts.google.com`, "Sign in to continue to avise.io", with Privacy Policy/Terms links), with correct scopes:
- Gmail: `gmail.readonly`, `userinfo.email`, `userinfo.profile`
- Google (Drive/Calendar): `calendar.readonly`, `drive.file`, `documents`, `gmail.send`, `userinfo.email`, `userinfo.profile`

Both carry a correctly signed `state` token (userId, organizationId, provider, nonce) and the right callback URL. Not completed further (no real Google account available to finish the login), but the server-side OAuth app registration and routing is confirmed correct.

**Note:** this fix did *not* touch the separate truncated-name display bug (finding #7) — that's still open and visible on the same page.

**Already-working integrations (for reference, unaffected by this round):** Outlook and Microsoft 365 both correctly redirect to real `login.microsoftonline.com` consent screens with correct client IDs and scopes. Granola correctly shows an API-key-entry modal with instructions (it uses an API key, not OAuth).
